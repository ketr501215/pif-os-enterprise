## 三、對 Q1 的初稿回答

**結論：你的理解方向正確，但「連結」需要再定義。**

| 動作 | 方式 | 說明 |
|------|------|------|
| 工作區引用 KB | 唯讀查詢（不複製原始資料） | KB 是權威，工作區只用計算結果 |
| 計算結果（MoS/Cramer）| 存工作區，不存 KB | KB 只存「種子值」（NOAEL/LD50） |
| 交付版 | 工作區 → 交付暫存 → Archive | 完成後封版，客戶配方留工作區不進 Archive |
| 版期管理 | Archive 內用日期+版號+SHA | 每版不可覆蓋 |

**「過渡頁連結」的實作建議：**
```
工作區 PIF 中的資料格 = 直接寫值（不用超連結）
但工作區 metadata 中記錄：
  - 引用的 KB 版本（KB_hash）
  - 引用日期
  - 如果 KB 更新，舊 PIF 不自動更新（需人工 re-generate）
```

## 四、對 Q2 的初稿回答（多租戶隔離）

### 方案 A：資料夾隔離（現行，適合 1-5 廠家）

```
12_CLIENTS_Private/
  廠家A_永悅/
    配方/
    PIF_Draft/
    交付暫存/
  廠家B_Biolume/
    ...
```
- 優點：最簡單，現在已在做
- 風險：靠人工紀律，無技術強制隔離
- 適用：Ray 一人操作，廠家不登入系統

### 方案 B：帳號隔離（適合 6-20 廠家，廠家會登入）

```
每個廠家有獨立 Google Drive 共享資料夾
廠家只看到自己的資料夾
KB 是只讀共享層
工作區在各自資料夾內
```
- 優點：Google 帳號層技術隔離
- 成本：需管理多個共享權限
- 適用：「導入」給廠家自己使用

### 方案 C：加密隔離（適合 20+ 廠家或法規要求）
- 每個廠家資料加密，金鑰各自持有
- 成本最高，目前不必要

## 五、「導入」的定義需先釐清（請 Ray 回答）

> 「導入是指分享工作區（一定帳號數）」

這句話有三種可能的意思，請確認是哪一種：

| 情境 | 說明 | 對隔離需求的影響 |
|------|------|----------------|
| A. Ray 操作，廠家只收交付物 | 廠家看不到系統，Ray 用一個帳號跑所有廠家 | 資料夾隔離就夠（現行方案） |
| B. 廠家登入系統自己填配方 | 廠家有帳號，但只看自己的 | 需 Google Drive 帳號隔離或獨立工作區 |
| C. 廠家買一套系統自己跑 | 廠家獨立部署，不共用 KB | 每個廠家一套完整系統 |

**目前建議：以情境 A 為基礎建架構，預留 B 的擴充介面。**

## 六、各文件類型的獨立 Gate 需求

| 文件類型 | 特殊需求 | Gate 差異 |
|---------|---------|-----------|
| PIF（現行）| 成分安全評估 | tox Gate + SA 簽核 |
| ISO 22716 GMP | 製程稽核記錄 | 廠房驗證文件 + 稽核員 |
| 綠色無毒認證 | 第三方標準 | 認證機構要求 |
| 期刊投稿 | 學術格式 + IRB | 不同 Gate 流程 |

**結論：每種文件類型應有獨立的 Gate 設定檔，不能共用同一個 Gate。**
