## 一、四大子系統依賴關係圖

```
法規知識庫
  │  （規定什麼成分有什麼限量/標準）
  ▼
原料知識庫 / 功效知識庫
  │  （每個成分的毒理數值 + 功效佐證，對照法規標準）
  ▼
文件管理系統（PIF / ISO 22716 / GMP / 綠色 / 期刊）
  │  （把 KB 數值轉成可交付的正式文件）
  ▼
版期管理 / 安全備份
     （封版、SHA、Archive、跨機同步）
```

**結論：上游錯，下游全錯。法規 KB 是整個系統的根。**

## 二、優先序排定（含理由）

| 序 | 子系統 | 優先級 | 理由 |
|----|--------|--------|------|
| **1** | **法規知識庫** | 🔴 P0 | 所有 MoS 計算的限量基準來自法規 KB；KB 錯誤會造成系統性偏差（已知 BUG-001/002/003 根因都在此層）|
| **2** | **原料知識庫 / 功效知識庫** | 🔴 P0（與法規 KB 並行）| 依賴法規 KB 定標準，但填充可並行進行；MoS/Cramer/NOAEL 都在這層；缺這層無法生成正確 PIF |
| **3** | **文件管理系統** | 🟡 P1 | 已有 70% 運作中（永悅 9 案、Biolume 已在交付）；繼續優化，但不能等 KB 全滿才推進 |
| **4** | **版期管理 / 安全備份** | 🟢 P2 | 已有基礎（git + Google Drive）；持續維護即可；最後才需要正式化 |

**⚠️ 例外：法規 KB 與原料 KB 同列 P0，但法規 KB 先建 Schema，原料 KB 緊接填充。**

## 四、每日進度報告制度

### 報告規則

1. 每位主責 Agent 每天開機後在自己的 `08_AGENT_OS/[Agent]/` 資料夾建立當日報告
2. 報告命名：`DAILY_[Agent]_YYYYMMDD.md`
3. 報告格式（固定，不得省略）：

```markdown
# Daily Report — [Agent] — YYYY-MM-DD

## 昨日達成
- [具體完成事項，含檔案路徑]
- [若無，明確寫「無」，不得空白]

## 今日計畫
- [具體任務，含預計輸出檔案]

## 阻塞事項
- [無 / 有：說明阻塞原因 + 需要誰解決]

## 子系統進度（自評）
| 子系統 | 昨日進度 % | 今日目標 % |
|--------|-----------|-----------|
| 法規 KB | xx% | xx% |
| 原料/功效 KB | xx% | xx% |
| 文件管理 | xx% | xx% |
| 版期備份 | xx% | xx% |
```

4. 每日收工前，Claude Code 彙整各 Agent 報告至 `00_POCC/DAILY_SUMMARY_YYYYMMDD.md`

### 彙整報告格式

```markdown
# Daily Summary — YYYY-MM-DD
## 系統整體進度
| 子系統 | 累積進度 | 今日變化 | 主責 |
|--------|---------|---------|------|
| 法規 KB | % | +% | Codex |
| 原料/功效 KB | % | +% | Codex |
| 文件管理 | % | +% | Claude |
| 版期備份 | % | +% | Claude |

## 今日亮點
## 今日阻塞
## 明日首要任務
```
